# 현재 상태

최신 로컬 상태. 편집기 좌우 독립 스크롤·미리보기 확대·공통 선택 버튼·선택 배경 이미지 지원을 반영했다. 사용자가 지정한 배경 이미지와 운영 콘텐츠는 보존했고, 새 추천 팔레트는 검토 사본에서만 확인했다. 커밋·push·배포는 수행하지 않았다.

## 최신 편집기·배경 이미지 검증

- 넓은 화면에서 폼과 미리보기가 독립적으로 스크롤한다. 상단 도구·탭·저장 버튼은 남는다. 1440×900에서 미리보기 높이는 421px에서 618px로 늘렸고, 760px 이하에서는 문서 스크롤을 유지한다.
- SegmentedControl을 입력 폼/JSON·모바일/넓게·켜짐/꺼짐에 재사용한다. 저장 값은 기존 boolean이며 키보드·저장 중 비활성화·생략 기본값을 유지한다.
- `resources.backgroundImage`를 선택 필드로 추가했다. 기존 이미지 검증·사용 자산 배포·assetUrl을 재사용하고 고정 cover 배경으로 표시한다. 생략 시 기존 배경을 사용하며 JSON Schema를 갱신했다. 로컬 편집 버튼이 배경에 가리지 않게 했다.
- 사용자가 `media/onari-backgroung.jpeg`를 배경으로 저장했다. 현재 색상은 유지했으며 흰 카드·푸른 회색 글자·하늘색 포인트 추천은 [편집 가이드](EDITING.md)에 정리했다.

전체 검사 7개 파일·57개 테스트, 현재 배경의 루트·/link-hub/·/linkhub/ 빌드/산출물 검사, 배경 생략 시 미사용 파일 제외, 추천 팔레트의 별도 빌드를 통과했다. 정적 preview의 파일 10개가 모두 200이며 편집기 화면/API/소스는 404다. 폼/JSON·저장·검증 오류·최근 정상 미리보기 유지·충돌 검사를 확인했다. 모바일 320/390px, 데스크톱과 낮은 900×600 화면에서 가로 넘침이 없다.

## 앞선 콘텐츠 반영

프로필 이름과 소개의 이모티콘·줄바꿈·해시태그를 원본대로 넣었다. 프로필과 Instagram/TikTok/YouTube 카드 이미지 4개는 원본 페이지에 표시된 JPEG를 내려받아 그대로 사용한다. 파일별 출처·크기·용도는 [리소스 문서](ASSETS.md), 바이트 해시는 [검증 기록](verification/linktree-content-qa.json)에 있다.

기존 SNS·카드 ID와 배열 순서, 공통 목적지 주소는 유지했다. 원본에 없는 상단 영어 문구·소개 보조 문구·카드 설명·배지·샘플 푸터는 제거했고 모든 SNS·카드는 원본처럼 새 탭에서 연다. 해시태그는 소개에 포함하고 별도 tags 목록은 비워 중복을 막는다. 링크 섹션의 탐색 제목은 SNS다.

기존 컴포넌트와 theme 설정으로 분홍색 배경·카드 색상·글자 크기를 맞췄다. Linktree 자체의 가입 배너·서비스 푸터는 포함하지 않는다. 파비콘과 공통 공유 UI는 현재 프로젝트의 것을 유지한다. 공유 이미지는 같은 Instagram 그림에서 1200×630 JPEG(`media/onari-og.jpg`, 약 64KB)로 생성했다.

앞선 콘텐츠 반영 당시 운영 설정 파일은 다섯 개이며 새 필드는 추가하지 않았다. 이후 위 배경 이미지 선택 필드를 추가했다. `products.json`의 빈 운영 목록, 기존 스키마·편집기·분석 연결 구조, 의존성과 package-lock.json은 유지했다. 초기 SVG/PNG 샘플은 기존 테스트용으로 남기고 운영 배포에서는 제외한다.

## 앞선 콘텐츠 검증

프로젝트 밖 임시 사본에서 확인했다. 실제 작업 폴더의 dist와 운영 상품 목록에는 테스트 데이터를 쓰지 않았다.

| 항목 | 결과 |
|---|---|
| 콘텐츠·이미지 실제 형식·용량·테마 대비 | 통과 |
| JSON Schema 동기화 / TypeScript / ESLint | 통과 |
| Vitest | 7개 파일, 52개 통과 |
| 루트 / /link-hub/ / 실제 /linkhub/ 빌드·verify:build | 모두 통과 |
| 배포 파일 HTTP 검사 | 9개 파일 200, MIME·바이트 수 일치 |
| 공개 HTML 메타데이터 | canonical·og:image의 도메인·하위 경로 확인 |
| 원본 이미지 4개 | 다운로드 바이트 SHA-256 일치, 브라우저 로딩 정상 |
| 모바일 320px / 390px / 데스크톱 1280px | 문서 너비가 화면 너비와 같음 |
| 운영 소개·이미지·SNS·카드 순서·새 탭 관계 | 확인 |
| 빈 상품 목록 | 상품 영역 전체 숨김 |
| 노출 5개 + 숨김 1개 / 기준 6 | 검색창 숨김 |
| 노출 6개 + 숨김 1개 / 기준 6 | 검색창 표시 |
| 검색·결과 없음·키보드 지우기 | 검색창 유지, 6개 복귀, 입력 포커스 확인 |
| 최대 길이의 한 단어 이름·소개·카드·상품 문구 | 320px에서 가로 넘침 없음 |
| 키보드 공유 패널 / 건너뛰기 링크 | 열기·닫기와 링크 영역 포커스 확인 |
| 샘플 이미지·편집기·개발 버튼의 빌드 제외 | 확인, preview 편집 화면·API·소스 404 |
| production 브라우저 콘솔 | 오류·경고 없음 |
| 사용자 서버 / 검증용 서버 | 사용자 서버 유지, 검증용 서버 종료 |

이미지 오류 테스트 2개는 이전 샘플 PNG 파일명을 고정해서 실제 운영 이미지 교체를 따라가지 못했다. 손상·확장자 불일치 검사가 설정의 seo.image를 대상으로 수행되도록 수정했다. 제목 순서·숨김 카드 렌더링 테스트도 현재 이미지와 새 탭 안내를 검증한다.

기본 JS는 약 236.4KB, CSS는 약 11.6KB이며 이미지 포함 전체 산출물은 387,862바이트다. 이 콘텐츠 교체 단계에서는 새 패키지나 스키마 필드를 추가하지 않았다. 편집 가이드·README·리소스 출처·배포 문서의 공유 이미지 경로도 함께 갱신했다.

## 현재 구조

- `content/site.json`: SEO·언어·테마·공통 목적지·리소스·공유 문구
- `content/profile.json`: 프로필·상단 문구·태그·SNS
- `content/links.json`: 기본 링크 영역
- `content/products.json`: 광고/상품 링크와 로컬 검색
- `content/footer.json`: 푸터

공개 페이지는 virtual module의 검증·정규화된 데이터를 Page에 전달하고 HTML 메타데이터도 같은 결과를 사용한다. 숨김 데이터·미사용 목적지·미사용 public 파일을 배포하지 않는다. 상품 검색은 브라우저 안에서만 수행하고 검색어를 전송하지 않는다. GA/Amplitude는 연결 지점만 있고 비활성이다.

로컬 편집기는 `npm run dev` 또는 `npm run editor`의 `/__editor/`에서 사용한다. 폼·JSON·같은 Page 미리보기·검증·revision 충돌 방지·동일 출처·세션 토큰 검사를 유지한다. 편집 화면/API/개발 버튼은 정적 빌드에서 제외된다.

## 공개 반영과 이전 배포 검토

이번 작업은 로컬 콘텐츠 수정이며 원격 설정·커밋·push·배포를 수행하지 않았다. 현재 공개 URL의 최신 상태도 이번 작업에서 재조회하지 않았다. 변경사항을 main에 반영한 후 Actions와 실제 page_url에서 새 이미지·문구·공유 미리보기를 확인해야 한다. 루트 주소로 전환하기 위한 저장소 이름 변경도 수행하지 않았다.

이전 [Actions 실행](https://github.com/onari-0/linkhub/actions/runs/40181686422/job/121133892697)은 npm ci·check 이후 Pages 조회 404로 실패했고, 당시 공개 API에서 has_pages=false를 확인했다. 당시 브라우저 계정에 저장소 관리 권한이 없었다. 이 내용은 이전 검토 시점의 기록이며 현재 원격 상태를 의미하지 않는다. 관리자 Pages 설정과 재실행, 기존 node_modules/dist 추적 정리 절차는 [배포 가이드](DEPLOYMENT.md)를 따른다.
