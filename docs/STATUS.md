## Actions 실패 검토

[실행 40181686422](https://github.com/onari-0/linkhub/actions/runs/40181686422/job/121133892697)는 Ubuntu에서 npm ci와 npm run check까지 성공하고, `Read the actual Pages URL`에서 Pages 사이트 조회 404로 실패했다. production 빌드·업로드·배포는 실행되지 않았다. 공개 저장소 API의 `has_pages: false`로 Pages 미활성화를 확인했고 예상 주소 `https://onari-0.github.io/linkhub/`도 404다.

현재 브라우저 계정에는 저장소 설정 관리 권한이 없다. 저장소 관리자가 Settings → Pages → Source를 GitHub Actions로 설정한 뒤 변경사항을 main에 반영하고 배포를 다시 실행해야 한다. 이번 작업은 로컬 수정·검토이며 커밋·push·원격 설정 변경·재배포는 수행하지 않았다.

두 워크플로의 액션 참조는 `checkout@v7`, `setup-node@v7`, `configure-pages@v6`, `upload-pages-artifact@v5`, `deploy-pages@v5`로 바꿨다. 다섯 태그의 존재와 Node 24/composite 런타임을 공식 API와 action.yml에서 확인했다. 액션 표기 변경은 Pages 미활성화와 별개의 개선이다.

추가로 node_modules 9,415개와 dist 7개 파일의 기존 Git 추적을 확인했다. 로컬 파일을 유지하면서 추적만 해제하는 절차, 정확한 `/linkhub/` 경로, 배포 후 외부 공유 완료 조건은 [배포 가이드](DEPLOYMENT.md)에 정리했다. 운영 JSON 다섯 파일과 사용자 변경은 보존했다.

AGENTS.md에 기능·설정 구조 변경 시 같은 작업에서 docs/EDITING.md를 반드시 갱신하고 이를 완료 조건에 포함하도록 명시했다. 작업 전 읽을 문서에도 편집 가이드를 추가했다.

스키마에 필드 설명·기본값·선택지·생략 동작 안내를 보강했고, 기존 상품 예시는 테스트 픽스처로 옮겨 실제 검색 테스트에 연결했다. 별도 예시 설정 파일은 유지하지 않는다.

## 현재 구성

운영 설정은 5개 파일이다.

- content/site.json: SEO·언어·테마·목적지·리소스·공유 문구
- content/profile.json: 프로필·상단 문구·태그·SNS
- content/links.json: 기본 링크 영역
- content/products.json: 광고/상품 링크와 검색
- content/footer.json: 푸터

기본 링크 아래에 상품 섹션을 추가했다. 노출 상품이 없으면 섹션 전체를 숨기며, 검색창은 노출 상품이 search.minItems(기본 6) 이상일 때 표시한다. 제목·브랜드·설명·키워드 검색, 검색 결과 없음, 초기화와 포커스 복귀를 지원한다. 실제 상품 정보가 제공되지 않아 운영 목록은 비워 두었고 검색용 가상 상품 데이터는 tests/fixtures/products.json에서 테스트 픽스처로 관리한다.

이미지 실제 해석·형식·용량 검사, 긴 문구·중복 태그 방어, 선택 프로필/푸터, 공통 목적지, 설정 기반 OG 생성·로고·파비콘·이미지 크롭, 테마 확장, 파일별 JSON Schema 자동완성을 반영했다. HTML과 React는 같은 정규화 데이터를 사용한다. 숨김 항목·미사용 목적지·미사용 public 파일은 배포 대상에서 제외한다.

스키마·테스트 데이터 정리와 배포 전 점검에서는 운영 설정 값과 기본값을 바꾸지 않았다. 로컬 편집기 구현에서도 현재 운영 JSON 5개의 바이트 해시가 작업 시작 전과 같음을 확인했다. 브라우저 저장·상품 예시는 프로젝트 밖 독립 사본에서 검증했다.

## 로컬 편집기

`npm run editor` 또는 `npm run dev`로 실행한 서버의 `/__editor/`에서 사용한다. 프로필·기본 링크·상품·디자인/공통·푸터를 입력 폼과 JSON으로 편집하고, 저장 전 초안을 같은 Page 컴포넌트로 미리볼 수 있다. 목록 추가·삭제·순서·카드 형태·노출 옵션, public 이미지 경로 후보, 모바일/넓게 미리보기를 지원한다. 이미지 업로드·Git push·배포는 수행하지 않는다.

미리보기는 원본 파일을 수정하지 않는다. 저장은 전체 초안을 기존 콘텐츠/이미지 검증으로 확인한 뒤 변경한 content 파일만 반영한다. 외부 수정·다른 탭의 오래된 revision은 409로 거부하고 초안을 유지한다. 기본값을 원본 파일에 일괄 추가하지 않는다. 로컬 접속·동일 출처·서버 세션 토큰을 검사한다.

프로필 이름 뒤에 자동으로 붙이던 마침표를 제거했다. 일반 개발 페이지 상단에는 ‘페이지 편집’ 이동 버튼이 있다. 개발 서버 전용 HTML 변환으로 삽입하며 편집기 방문자 미리보기·정적 빌드·npm run preview에는 포함하지 않는다. /link-hub/ 같은 하위 경로도 적용한다.

편집 화면·API는 개발 서버에만 있고 정적 산출물에서는 제외된다. 실제 production preview에서 일반 페이지는 200, 편집 화면·API·미리보기·소스 경로는 모두 404였다. verify:build에도 편집기 혼입 검사를 추가했다. 공개 페이지는 기존 동작을 유지한다.

## 실행과 외부 배포

Homebrew Node 24.18.0과 npm/npx 11.16.0을 사용한다. 새 의존성은 추가하지 않았다. 직전 npm ci 감사에서 취약점은 0건이었다. 이번 수정 전부터 사용자가 실행한 개발 서버(5173)는 유지했고, 이번 작업에서 띄운 검증용 서버는 종료했다.

Git 초기화·origin 연결·main push는 사용자가 완료한 상태이며 이를 재초기화하거나 원격에 쓰지 않았다. 이번 작업의 로컬 코드·빌드·워크플로 정적 검사는 통과했다. 공개 저장소임을 확인했으며 Pages 활성화와 배포 재실행이 남았다. Actions 정책·환경 보호 규칙은 관리자 계정에서 필요 시 확인한다. GA/Amplitude는 연결 지점만 있고 데이터 전송은 비활성이다. 검색어는 수집하지 않는다.

OS 네이티브 공유 시트의 실제 외부 전송은 수행하지 않았다. 공유 성공·취소·폴백은 단위 테스트에 포함되어 있다.
